## 1. 背景与被否决方案

当前 `BackupStorage` 把备份明文（JSON）写入系统「下载」共享目录（MediaStore Downloads），
目的是**卸载 APP 后备份依然保留、重装可恢复**。明文落盘意味着任何能访问「下载」目录的
App / 用户 / 传输链路都能直接读到全部账目数据，存在隐私泄露风险。

### 为什么不用 Android Keystore（AES-GCM）

一个直觉方案是「用 Android Keystore 生成 AES-GCM 密钥加密备份」。但该方案与备份语义**自相矛盾**：

- Android Keystore 中的密钥**随 App 卸载被系统销毁**，且不可导出。
- 备份的核心诉求恰恰是「**卸载后仍可恢复**」。
- 卸载 → Keystore 密钥没了 → 重装后无法解密旧备份 → 备份等于作废。

因此 Keystore 方案被否决。正确方向是：**密钥不依赖设备/安装态，而是从用户口令派生**。

## 2. 目标方案：用户口令 + PBKDF2 派生密钥 + AES-GCM

核心思想：加密密钥由**用户口令**经 PBKDF2 派生得到，不落盘、不依赖 Keystore。
只要用户记得口令，卸载重装乃至换设备均可解密恢复。

### 2.1 密钥派生（KDF）

- 算法：`PBKDF2WithHmacSHA256`
- 迭代次数：`>= 120000`（随硬件能力可上调，写入加密头以便未来调参兼容）
- 盐（salt）：每次加密**随机 16 字节**，明文存入加密头（盐不需保密）
- 派生密钥长度：256 bit（AES-256）

```
key = PBKDF2(password, salt, iterations, keyLen=32) // HmacSHA256
```

### 2.2 对称加密

- 算法：`AES/GCM/NoPadding`
- IV / Nonce：每次加密**随机 12 字节**，明文存入加密头
- Tag 长度：128 bit（GCM 认证标签，保证机密性 + 完整性/防篡改）
- 明文输入：现有 `generateExportJson()` 产出的 UTF-8 JSON 字符串

## 3. 加密文件头格式

密文文件采用「自描述头 + 密文」结构，所有参数随文件走，便于跨设备/跨版本解密。
建议整体做 Base64 后写文本文件（沿用现有 `.json` 之外新增后缀，如 `.jbak`），或直接写二进制。

字段布局（二进制布局，网络字节序）：

| 偏移 | 长度(byte) | 字段 | 说明 |
|------|-----------|------|------|
| 0 | 4 | Magic | 固定 `JBEN`（0x4A 0x42 0x45 0x4E），用于识别加密备份 |
| 4 | 1 | Version | 加密头版本，起始 `1` |
| 5 | 1 | KdfId | KDF 标识，`1`=PBKDF2WithHmacSHA256 |
| 6 | 4 | Iterations | PBKDF2 迭代次数（Int, 大端） |
| 10 | 1 | SaltLen | 盐长度（=16） |
| 11 | SaltLen | Salt | 随机盐 |
| .. | 1 | IvLen | IV 长度（=12） |
| .. | IvLen | Iv | 随机 IV/Nonce |
| .. | 剩余 | Ciphertext | AES-GCM 密文（含末尾 16 字节 GCM Tag） |

> 头中所有参数均**非机密**（盐、IV、迭代次数公开不影响安全），保密性完全由用户口令保障。

## 4. 旧明文备份兼容识别

恢复流程需同时支持「历史明文备份」与「新加密备份」，识别策略：

1. 读取文件头前 4 字节：
   - 等于 Magic `JBEN` → **加密备份**，走「弹出口令输入 → PBKDF2 派生 → AES-GCM 解密 → 得到 JSON → 交给 `importFromJson`」。
   - 否则 → 尝试按**旧明文 JSON** 解析（首个非空白字符为 `{`）。
2. 解密失败（GCM Tag 校验不过）→ 判定为**口令错误或文件损坏**，提示用户重输口令，**不得**误导为「备份为空」。
3. `importFromJson` 本身保持不变：无论明文还是解密后 JSON，进入统一恢复流程（version 兼容逻辑已具备）。

## 5. 口令不可找回提示（UX 硬约束）

由于密钥完全由口令派生、且不做任何托管：

- **口令一旦遗忘，对应加密备份永久无法恢复**（这是安全性的必然代价，不是缺陷）。
- 设置加密备份口令时，UI 必须**醒目提示**：「口令无法找回，请自行牢记；忘记口令将导致该备份无法恢复」。
- 建议二次确认输入口令，降低误输入风险。
- 不提供「找回口令 / 重置口令」入口（任何此类入口都意味着密钥可被绕过，破坏加密意义）。

## 7. 安全性小结

| 威胁 | 缓解 |
|------|------|
| 备份文件被他人读取 | AES-256-GCM 加密，无口令无法解密 |
| 备份文件被篡改 | GCM 认证标签校验，篡改即解密失败 |
| 卸载/换机后无法恢复 | 密钥由口令派生，不依赖 Keystore/设备 |
| 彩虹表/暴力破解 | 随机盐 + 高迭代 PBKDF2 显著提高破解成本 |
| 口令遗忘 | 设计上不可恢复，UI 明确告知（安全取舍） |
