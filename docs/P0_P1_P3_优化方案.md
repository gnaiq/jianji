## P3-1：账户余额改为 SQL 聚合

### 优先级：P3
### 类型：性能优化
### 预估工作量：0.5 天

### 修改目标文件

| # | 文件 | 操作 | 修改范围 |
|---|------|------|---------|
| 1 | `data/TransactionDao.kt` | 修改 | 新增 `getAccountBalances()` 查询 |
| 2 | `ui/viewmodel/TransactionViewModel.kt` | 修改 | `accountBalances` 改用 SQL 聚合 |

### 具体修改内容

#### 1. `data/TransactionDao.kt` — 新增聚合查询

```kotlin
// 新增方法：按账户聚合余额（含收入/支出/转账双边）
// 注意：SQLite 无 PIVOT，用 UNION ALL 将三种交易类型 + 转账目标账户统一为 (accountId, delta) 对
@Query("""
    SELECT accountId, SUM(amount_cents) as balance FROM (
        SELECT accountId, amount_cents FROM transactions WHERE type = 'INCOME' AND deleted_at IS NULL
        UNION ALL
        SELECT accountId, -amount_cents FROM transactions WHERE type = 'EXPENSE' AND deleted_at IS NULL
        UNION ALL
        SELECT accountId, -amount_cents FROM transactions WHERE type = 'TRANSFER' AND deleted_at IS NULL
        UNION ALL
        SELECT toAccountId AS accountId, amount_cents FROM transactions
        WHERE type = 'TRANSFER' AND deleted_at IS NULL AND toAccountId IS NOT NULL
    ) WHERE accountId IS NOT NULL
    GROUP BY accountId
""")
fun observeAccountBalances(): Flow<List<AccountBalance>>
```

同时新增数据类（同文件或新建 `data/AccountBalance.kt`）：

```kotlin
data class AccountBalance(
    val accountId: Long,
    val balance: Long  // 单位：分
)
```

#### 2. `ui/viewmodel/TransactionViewModel.kt` — 替换余额计算

```kotlin
// 修改前（68-92 行，O(n) 内存扫描）
val accountBalances: StateFlow<Map<Long, Double>> = transactions
    .map { txs -> ... 遍历 txs 逐笔计算 ... }
    .stateIn(viewModelScope, SharingStarted.Eagerly, emptyMap())

// 修改后（SQL 聚合，O(1) 内存）
val accountBalances: StateFlow<Map<Long, Double>> =
    transactionRepository.observeAccountBalances()
        .map { list -> list.associate { it.accountId to it.balance / 100.0 } }
        .stateIn(viewModelScope, SharingStarted.Eagerly, emptyMap())
```

同时在 `TransactionRepository` 中新增透传方法：

```kotlin
fun observeAccountBalances(): Flow<List<AccountBalance>> =
    transactionDao.observeAccountBalances()
```

### 预期效果

- 余额计算从 O(n) 内存扫描降为 SQL 聚合（利用数据库索引），万条交易场景下性能提升显著
- 代码量减少约 20 行（删除手写循环逻辑）
- `SharingStarted.Eagerly` 保持，确保 `accountBalances.value` 快照读取有效

### 风险控制

- Room Flow 自动在 transactions 表变更时重新查询，与现有触发机制一致
- 删除 `transactions` 对 `accountBalances` 的隐式依赖（原 `transactions.map{}`），改为独立的 DAO Flow
- `AccountBalance` 类型为 Long 分，上层除以 100.0 还原为 Double，与现有 `Map<Long, Double>` 接口兼容
- 消费方（`JianjiApp.kt:307`、`SettingsScreen.kt:335`）读取 `accountBalances.value`，接口不变
- `SharingStarted.Eagerly` 同时兼任上游 Flow 的常驻订阅者，与现有行为一致
