## 二、修复实施（最小范围改动）

### B1-4 / B5-6 分类删除级联误伤
- `data/Transaction.kt`：FK `onDelete = CASCADE` → **`NO_ACTION`**。
- `data/JianjiDatabase.kt`：新增 `MIGRATION_7_8`（重建 `transactions` 表，外键改 `NO ACTION`，数据无损），version 7→8，注册迁移。
- `data/CategoryDao.kt`：新增 `getBySystemName`、`reassignCategory(sourceId,targetId)`（仅改挂**可见**交易，`deleted_at IS NULL`）。
- `data/CategoryRepository.kt`：新增 `UNCLASSIFIED_NAME` 常量 + `ensureUncategorized()` + `reassignTransactionsToUncategorized()`；`deleteCategory` 改为"先 reassign 可见交易到未分类兜底分类，再删"，并**禁止删除系统分类**。
- `ui/screens/CategoryManagementScreen.kt`：删除确认文案改为"交易归入未分类、回收站保留"，不再误导为"永久删除"。

### B3-4 余额浮点
- `ui/viewmodel/TransactionViewModel.kt`：提取 `internal fun computeAccountBalancesCents(txs)`（Long 分累加），`accountBalances` 仅在输出时 `/100.0`，消除逐笔 Double 累加漂移。

### D2-1 周期双算法
- `TransactionViewModel.nextRunAfter` 改为委托 `computeRecurringNextRun`（统一 dayOfWeek 语义），消除 WEEKLY 用 `plusWeeks` 跳过星期导致的重复/漏记。

### P6-1 备份加密
- `utils/BackupCrypto.kt`（新增）：PBKDF2withHmacSHA256(120k) + AES/GCM/NoPadding(12B 随机 IV)，格式 `v1:<salt>:<iv>:<ct>`。
- `utils/AppPrefs.kt`：新增备份口令读写（空=不加密，向下兼容）。
- `utils/AutoBackup.kt`：导出/操作前快照按口令加密（失败退明文，不阻断）。
- `utils/DataImportManager.kt`：`importFromJson` 透明解密（加密则解密，明文原样），向下兼容旧备份。
- `ui/screens/settings/BackupDialogs.kt`：恢复时传入 context 以读取口令解密。

### P6-2 加固
- `proguard-rules.pro`：在既有 `utils.**` keep 基础上显式点名 `ImportData`/`*Import`/`BackupCrypto`，防未来 DTO 移包丢失 keep 导致 release 崩溃。

## 六、紧急修复：v1.6.26 → v1.6.27 升级闪退（数据库迁移校验失败）

### 现象
用户从 v1.6.26（DB v7）升级到 v1.6.27（DB v8）后 App 打开即闪退，提示数据库问题。

### 根因
`MIGRATION_7_8` 重建 `transactions` 表时，外键写为 `ON DELETE NO ACTION`。但实体 `Transaction.kt`
的 `onDelete = ForeignKey.NO_ACTION` 在 Room 生成的 v8 期望 DDL 中**省略 `ON DELETE` 子句**
（NO ACTION 是 SQLite 默认，Room 不显式写出）。Room 迁移后做**精确字符串比对**，
`ON DELETE NO ACTION` 与省略写法不一致 → `IllegalStateException: Migration didn't properly handle transactions`
→ 启动即闪退。

### 修复（v1.6.28 / versionCode 61）
- `JianjiDatabase.kt` 的 `MIGRATION_7_8`：重建表外键改为 `FOREIGN KEY(categoryId) REFERENCES categories(id)`，
  与 Room 对 `NO_ACTION` 生成的 DDL 精确一致。
- 新增 `androidTest/.../Migration7to8Test.kt`：**不依赖 schemas/ 文件**，手工建 v7 结构库（含旧 CASCADE 外键
  + 一条交易），触发 `MIGRATION_7_8` 升级到 v8，断言：① 不抛迁移校验异常（升级不闪退）；② 交易数据保留；
  ③ 升级后删分类不再级联删交易（验证外键确为 NO ACTION，B1-4/B5-6 修复在升级路径生效）。
- 版本升至 v1.6.28 重新发布（旧 v1.6.27 release 保留，用户需升级到 v1.6.28）。

### 验证
CI run 30911099528 = success，Release `jianji-v1.6.28.apk` 已发布：
https://github.com/gnaiq/jianji/releases/tag/v1.6.28

### 经验（迁移铁律，写入 memory）
Room 迁移重建表时，DDL 必须与实体注解生成的 schema **逐字符一致**：
- 外键 `NO_ACTION` → **省略 `ON DELETE` 子句**；`CASCADE` → 显式 `ON DELETE CASCADE`。
- 实体声明的每个索引都必须在重建后 `CREATE INDEX`（参考 `MIGRATION_5_6` 已建全 5 个索引的做法）。
- 任何 DB 版本迁移改动后，必须加一个 v(N-1)→v(N) 升级冒烟测试，在 CI（connectedCheck）验证升级不闪退、数据不丢。
